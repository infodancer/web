# media

A reusable image upload/store/serve component for infodancer websites. It backs
mdedit's image references and blog's embedded images: a host mounts it, an
author uploads an image, and `media` makes it safe, stores it, and serves it
under a stable content-addressed URL.

It is the storage/serving third of the image split — the editor
([`infodancer/ui/mdedit`](https://github.com/infodancer/ui)) inserts a
reference and the sanitizer
([`infodancer/ui/markdown`](https://github.com/infodancer/ui)) decides what
`<img>` survives; neither stores bytes. `media` does.

```go
import "github.com/infodancer/web/media"
```

## Why it exists

Serving user-uploaded files is a classic stored-XSS and privacy vector — an SVG
with script, a polyglot sniffed as HTML, EXIF GPS leakage, a decompression
bomb. `media` concentrates that risk in one audited, tested place, the way
`markdown` concentrates Markdown sanitization.

## The pipeline

`Process` is the security core, and it touches no database:

1. Bound the input size; ignore the client's declared content-type and filename.
2. Sniff the format from content — extension and client type are never trusted.
3. Allowlist **PNG, JPEG, GIF, WebP**.
4. Guard dimensions from the header *before* decoding (decompression-bomb guard).
5. Reject animation (animated GIF and animated WebP), or, with `FlattenAnimation`,
   keep only an animated GIF's first frame; reject SVG (not a raster format).
   GIF frames are counted from the block structure, never by decoding them all.
6. Decode, scale down to `MaxWidth`/`MaxHeight` if set, and **re-encode** to a canonical raster (lossless WebP for PNG,
   static GIF, and WebP; q85 JPEG for JPEG, which lossless would only bloat) —
   strips EXIF, kills polyglots. WebP encoding is pure Go (no cgo).
7. Content-address by SHA-256; identical uploads dedupe.

## Categories — server-side, one handler each

An image is never a free-floating upload: it is tied to some owning record (a
campaign, a creature, a character) that the user may write to, and that
record's *kind* is the **category**. The category is a property of the mount,
not the request — the client never sets it. You configure the store once and
register one handler per category over it:

```go
pool := /* the host's *pgxpool.Pool */
if err := media.Migrate(ctx, pool); err != nil { /* ... */ }

store := media.NewStore(pool)             // metadata, shared
blobs := media.NewPostgresBlobStore(pool) // bytes, shared (default backend)

campaignImages, err := media.NewHandler(store, blobs, media.Config{
    Category:       "campaign",            // fixed, server-side
    MaxUploadBytes: 10 << 20,
    MaxPixels:      25_000_000,
    PublicBaseURL:  "/media/campaign",     // where THIS handler's GET is mounted
    // Authorize gates the upload and names the owning record (subject). The
    // host derives the campaign id from its own route/session and checks write
    // permission; ok=false rejects the upload.
    Authorize: func(r *http.Request) (subject string, ok bool) {
        id := r.PathValue("campaign")      // from the host's route
        return id, host.MayEditCampaign(r, id)
    },
})
mux.Handle("/media/campaign/", http.StripPrefix("/media/campaign", campaignImages.Routes()))
// ...and likewise a "creature" handler, a "character" handler, etc.
```

Bytes land at `<root>/campaign/ab/cd/<hash>` (or the `media_*` tables keyed by
`(category, hash)`), physically separating campaign images from creature images
rather than relying on a metadata column alone.

- `POST {mount}/` — multipart field `image`. On success: `201` + JSON
  `{ "url": "...", "width": N, "height": N }` (plus `"thumbnails"` when
  configured, see below). mdedit's adapter inserts `![](url)`. The `url` sits
  under this handler's `PublicBaseURL`, so the category is in the URL because the
  host mounted the handler there.
- `GET {mount}/{hash}[.ext]` — serves the bytes (scoped to this handler's
  category) with `Content-Type`, `X-Content-Type-Options: nosniff`, immutable
  `Cache-Control`, and `ETag`.

`media.Store.ListBySubject(ctx, category, subject)` returns every image tied to
one record (e.g. all images for one campaign).

## Thumbnails (pregenerated, autogenerated)

Configure `Config.Thumbnails` and every upload also produces those derived
sizes, generated at upload time through the same safety pipeline (re-encoded,
EXIF stripped, polyglots killed) and content-addressed by their own bytes:

```go
media.Config{
    Category:      "campaign",
    PublicBaseURL: "/media/campaign",
    Thumbnails: []media.ThumbnailSpec{
        {Name: "thumb",  MaxWidth: 320,  MaxHeight: 320, Fit: media.FitCover},
        {Name: "medium", MaxWidth: 1024, MaxHeight: 1024},  // Fit defaults to FitInside
    },
}
```

- `FitInside` scales down to fit within the box, aspect ratio preserved (output
  dims vary). `FitCover` scales to cover then center-crops to exactly the box (a
  uniform grid). Neither ever upscales.
- A thumbnail is just another safe, content-addressed blob in the same category,
  so the **GET path serves it unchanged**. The upload response gains a
  `"thumbnails"` array (`name`/`url`/`width`/`height`), omitted entirely when no
  specs are configured.
- `media.Store.ListVariants(ctx, category, parentHash)` returns an original's
  derived sizes.
- `media.BackfillThumbnails(ctx, store, blobs, cfg)` fills missing sizes for
  images stored before the feature (or after adding a new size). It is
  idempotent — re-running creates nothing new.

## Storage

Bytes default to Postgres `bytea`, behind the `BlobStore` seam (every method
takes the category, so one store serves them all):

```go
type BlobStore interface {
    Put(ctx, category, hash, contentType string, data []byte) error
    Get(ctx, category, hash string) (data []byte, contentType string, err error)
    Has(ctx, category, hash string) (bool, error)
}
```

Backends, all behind the same seam (swap one for another with no other change):

- `PostgresBlobStore` — bytes in Postgres `bytea` (default).
- `FilesystemBlobStore` — bytes on disk under a root dir, content-addressed and
  category-sharded (`<root>/<category>/ab/cd/<hash>`) with a content-type
  sidecar; the same filesystem-image posture osg uses, with atomic writes. Bytes
  are still served through the handler (so `nosniff` + headers apply), never a
  bare directory listing.
- `MemoryBlobStore` — in-memory, for tests and no-database dev mounts.

```go
blobs, err := media.NewFilesystemBlobStore("/var/lib/app/media")
```

## What the host owns

Authentication, authorization, CSRF, and the rate-limit policy on the public
intake — exposed as hooks on `Config`. The handler adds a same-origin guard and
the `Authorize` gate, but the host decides who may upload.
